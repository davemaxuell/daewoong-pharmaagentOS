## Implemented behavior

- Validated Railway metadata, exact platform/healthcheck hosts, injected `PORT`,
  managed secret variables, remote persistent storage and metadata-only logs.
  Existing production JWT, schema and CORS guards remain active.
- Separate `app.background_worker` ingestion and research loops, clean signal
  shutdown, lane-specific recovery, durable daily scheduling and PostgreSQL
  transaction locks protecting schedule admission and ingestion claims.
- Fixed refresh cutoffs revisit new/changed/stale listing entries within the
  existing rolling discovery window. Daily schedules do not build a backlog
  while an ingestion job is pending/running. Existing source/version checkpoints
  and bounded retries handle interruption and partial failures.
- DataTables pagination follows actual returned row counts, validates counts and
  rows, and rejects premature empty/repeated pages rather than claiming success.
- `app.fda_probe` checks live acquisition/parsing without database writes.
- Server-side `EXTERNAL_API_BASE_URL` controls all frontend backend clients;
  `RESEARCH_WORKER_MODE=poll` suppresses Vercel HTTP wakeup once Railway is ready.
  Existing bindings and wake behavior remain the default.
